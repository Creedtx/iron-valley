# Iron Valley: Factory Rising

A 1973 idle factory game in three.js: inherit grandfather's crate workshop and grow it into a regional
manufacturer. This repository holds the game, the Blender Python kit that generates every 3D model, and the
headless-Chrome test tools.

## Play it on your phone (Termux)

`dist/phone/` is a complete offline copy of the game: three.js, fonts and models are all local, nothing is
fetched from the internet. Any web server can serve it; Termux has one built in through Python.

One time, in Termux:

```bash
pkg update && pkg install -y python git
```

Get the game, either from GitHub:

```bash
git clone https://github.com/Creedtx/iron-valley.git
cd iron-valley/dist/phone
```

or from the zip (`iron-valley-phone.zip`) saved in your phone's Downloads folder:

```bash
termux-setup-storage                       # allow Termux to read Downloads (one time)
mkdir -p ~/iron-valley && cd ~/iron-valley
unzip -o ~/storage/downloads/iron-valley-phone.zip
```

Then start the server and leave Termux running:

```bash
python -m http.server 8080
```

Open Chrome on the same phone and go to **http://localhost:8080**. Add it to the home screen from Chrome's
menu for a full-screen icon. Stop the server with Ctrl+C (Termux's CTRL key, then C).

To update after new commits: `cd ~/iron-valley && git pull` (or unzip the new zip over the old folder).
Your save game lives in the browser and is kept between updates.

Rebuild the phone copy from `game/` after changing the game: `cd tools && npm install && cd .. && node tools/package.mjs`
(writes `dist/phone/`, `dist/playables/` and their zips).

## Build the models

Needs Blender 4.4 or newer (tested on 5.3) and Node 18+.

```bash
cd tools && npm install && cd ..           # one time: optimiser + validator

blender -b -P blender/build.py              # build every model
blender -b -P blender/build.py -- --only worker,saw_bench
blender -b -P blender/build.py -- --fast --no-render   # quick iteration, no bake, no renders
```

Without the Blender app you can `pip install bpy` (Python 3.13 for bpy 5.x)
and run `python3 blender/build.py` with the same flags.

Outputs:

| Path | What |
|---|---|
| `models/<name>.glb` | Game-ready files: welded, quantized, meshopt-compressed (EXT_meshopt_compression), validated |
| `renders/*.png` | Previews from the game's fixed camera angle |
| `reports/budget.md`, `budget.json` | Size, triangles, draw calls, clips per model |
| `build/raw/*.glb` | Blender's unoptimised export, for debugging |

The build exits with code 1 if any model breaks its budget (each model sets its
own; 400 KiB per file at most) or if an animated model fails `tools/anim_check.mjs`,
so it can gate CI.

## How the models are built

1. `ivlib/geo.py` — a `Part` collects boxes, cylinders, spheres and extruded
   profiles with palette colours. Each Part becomes one mesh object, so a
   machine is 3–10 draw calls, not hundreds.
2. `ivlib/bake.py` — Cycles bakes ambient occlusion into vertex colours, with a
   temporary floor so machines darken where they meet the ground. This is the
   strategy's "baked shading": the game needs no shadow maps on low-end phones.
3. `ivlib/export.py` — GLB export with named nodes, then `tools/optimize.mjs`
   welds, quantizes, meshopt-compresses and runs the Khronos validator.
   Animation is exported as **sampled linear keys**, never cubic splines:
   compression stores keys in 16 bits, which breaks spline tangents (build 0.4's
   idle clip swung the upper body about 30° because of it).
   `tools/anim_check.mjs` fails the build if a calm clip (idle, inspect, phone,
   sit) bends the spine past its limit or any channel is a cubic spline.
4. `ivlib/render.py` — orthographic preview at 45° / 35°, the game camera.

### Worker palette

Character meshes are UV-mapped into a 32×1 texture, one texel per slot:

`skin hair shirt suit pants boots hat eyes metal stache belt glove tie eye-whites cheeks soles vest stripe tool board paper lens muff cord` (+8 spare)

Roles are colour swaps (`ROLES` in `ivlib/palette.py`): operator blue with a
yellow hard hat, loader olive with a hi-vis vest, electrician navy with a blue
hard hat, mechanic orange with a dark cap, supervisor charcoal with a white
hard hat and orange vest. In three.js:

```js
const data = new Uint8Array(32 * 4);              // fill RGBA per slot
const tex = new THREE.DataTexture(data, 32, 1);
tex.colorSpace = THREE.SRGBColorSpace;
tex.magFilter = tex.minFilter = THREE.NearestFilter;
tex.needsUpdate = true;
workerMesh.material = workerMesh.material.clone();
workerMesh.material.map = tex;
```

Use `SkeletonUtils.clone()` per worker and one `AnimationMixer` each.
Set a moustache to the skin colour to hide it.

## Adding a model

Create `blender/assets/<name>.py` with a `build(mats)` that returns
`(root, {"kind": ..., "budget_kib": ...})`, add the name to `ORDER` in
`build.py`, and run the build. Use palette names from `ivlib/palette.py`
rather than new hex values, so the factory keeps one look.

## YouTube Playables bundle

```bash
node tools/package.mjs          # dist/playables/ and dist/iron-valley-playables.zip
node tools/check_bundle.mjs     # size, file and outside-URL rules
(cd dist/playables && python3 -m http.server 8766) &
node tools/playables_check.mjs http://localhost:8766/   # SDK lifecycle against a stand-in SDK
```

The artifact build (`game/`) loads three.js from a CDN and packs the models as base64 in `models.js`.
The Playables build is self-contained:

| | Artifact (`game/`) | Playables (`dist/playables/`) |
|---|---|---|
| SDK | none (runs as the web build) | `https://www.youtube.com/game_api/v1`, first script on the page |
| three.js | import map to jsDelivr | `three.js`: r170 tree-shaken to what the game uses, minified |
| Game code | `game.js` as written | `game.js` minified; browser-only code (Page Visibility) compiled out |
| Fonts | Google Fonts | local woff2 (Oswald, Barlow, Special Elite; Latin) |
| Models | `models.js`, all at once | `models/*.glb`; level 2's load when level 2 starts |

`playables_check.mjs` checks, against a stand-in SDK: firstFrameReady first, gameReady only after the
loading screen is gone, loadData awaited before any saveData, saves under 64 KiB, an old (version 5)
save upgrading cleanly, onPause stopping the loop and rendering until onResume, YouTube mute respected
in both directions, no outside network calls, and level 2 models downloading only at level 2.
Known SHOULD note: `three.js` is about 558 KiB, above the 512 KiB per-file recommendation (the MUST
limit is 30 MiB). Run Google's own Playables test suite before submitting.

## Production counts and the warehouse (build 0.11)

How much is left to make is counted from what physically exists: crates the truck still needs, minus
crates on the pallet, in loaders' hands and in the warehouse (pipes the same way). The ticket's "Cut" figure
is derived from the same totals. Build 0.10 kept a running tally instead, and a reload dropped crates that
were in a loader's hands while the tally still counted them, so the saw thought the order was cut and the
truck waited for ever (order #34). Saves now put carried items back on their stack, and a lost item, for
any reason, is simply made again.

The warehouse opens at level 2 once the pipe mill runs, the back yard is cleared and 10 pipes have shipped:
a pad in the yard ($1,500), a contractor, then a shed with racking (24 crates and 12 pipes, more with the
Warehouse racking upgrade). With "Make to stock" on (office, Stock), the saw and the mill keep working
between orders until the warehouse is full; loaders shelve everything the open order does not need and ship
from stock when the line cannot cover a docked truck.

## Level 3: Local Manufacturer (build 0.12)

The farmer's North field lies behind the dock apron. The owner buys it on a pad by the farm gate ($2,500); a
contractor then installs the tool press on it ($1,800). The press takes steel coils from the same coil bay as the
pipe mill (6 tools a coil, 4 s a tool, 4.5 kW) and puts tool boxes on a rack for the truck; with all three machines
running the load is about 18.6 kW, just over Generator Mk II's 18. Orders now mix crates, pipes and tools, and grow
with the level (`econ` in progression.js). Machine faults need a spare part from the shelf on the field; with none
the mechanic makes do at about a third of the speed. Spare parts and the trading licence are bought in the office.
Charter: $8,000, reputation 62%, 50 tools shipped, field and press, 5 issues fixed and the licence. Upgrades:
Tool press speed, Sturdier parts (fewer breakdowns on every machine) and Spare-parts shelf. The coil bay was
turned along the apron's east edge so the apron leads to the field, and operators are capped at one per machine.

## The owner starts alone; the wider valley (build 0.13)

Follows the Level Bible and the Master Design Doc.

- **Level 1 by hand.** A new game opens on the grandfather's letter, then Gus Mallory (the old foreman) at the
  gates. There is nobody on the payroll and $400 in the till. The owner answers the phone, stands at the saw to cut
  (any machine runs while he stands at its operator spot and nobody else works it), carries up to five crates on his
  back from the pallet to the truck's tailgate, signs and collects. With no loaders he also tops up the generator
  at its fuel spot and the saw feeds itself from the stock room; the supplier's driver unloads his own lorry. The
  opening ends with the first two hires ($80 each). From then on the crew works and the owner only instructs.
  Charter: $2,000 earned (the starting $400 does not count), reputation 60%, 2 orders, the back yard, an operator
  and a loader.
- **Roles by level.** Electrician and mechanic open at level 3, the supervisor (and slacking) at level 4.
  Locked departments in the Staff tab say the level they open.
- **Breakdowns by level.** Levels 1 and 2 have none: only the old generator stalls for 3 s now and then until it is
  tuned (Generator Mk II never stalls). From level 3 an issue comes about every 3 minutes: a jam, a worn part (needs
  a spare from the shelf) or a power cut (machines at half speed; passes by itself in 30 s). Issues are known at
  once; a broken machine runs at half speed; an issue left open over 2 minutes costs 1 reputation; with nobody of
  that trade a contractor comes after 60 s ($45). The owner can fix any issue by hand at half a mechanic's speed.
  The first tool order is guided: the press jams halfway, the owner fixes it, then hires a mechanic.
- **Reputation.** Starts at 60. On time +2, early (under half the deadline) +3, late −3 and half pay, declined −2,
  given up −6 (Orders tab). Bands: Shaky <50 (smaller orders), Known, Trusted 65+ (larger orders, faster permits),
  Respected 80+, Renowned 90+ (+10% pay). Deadlines are at least 180 s; the very first order has none.
- **Land deals.** Plots are fenced with a For-sale sign from the start. Level 2 buys the North field from Abel
  Thorne ($800), level 3 buys the scrapyard from Rusty Pike ($1,600), each through Vera Lind (5% fee). Three
  offers: pay, negotiate (1% off for every 2.5 reputation over 50, up to 20%, permit twice as long) or the
  sweetener (two free hires / a free crate machine at level 4). Then a 30 s council permit and a 60 s site job by
  Big Tom Okafor's crew. Prices from the Bible: pipe machine $600, tool machine $1,200, licence $160.
- **Story cards** pause the game: the letter, the Valley Courier at each level start, a person's first scene, and
  the land offers. The new Town tab lists the land, the people met and the trading licence.

Old saves (version 6 and earlier) keep their crew and skip the new opening. To play the new opening from such a
save, use **Office → Charter → Start a new game** (two taps): it replaces the saved game with a new one and reloads
into the grandfather's letter (`tools/newgame_check.mjs` tests it).

## Level 4 fixes (build 0.14.1)

- **The supervisor's ring stays at the post.** Build 0.14 drew the 6 m zone ring under the supervisor's feet, so
  a big blue circle went round the site with her whenever she signed a truck or briefed the crew. The zone now
  belongs to the post: it counts while she is on duty near it, the ring is drawn there for six seconds when the
  post is set (and when Wider zone grows it), then fades out. With a post she only chases slackers and idlers
  inside her zone.
- **No more blinking yard markings.** The yellow forklift bays and walkways sat 4 mm over the gravel, too close
  for a phone's 16-bit depth buffer, so they flickered as the camera moved. Ground markings and pads now use a
  depth offset by layer (`decal()`), the yard paint is opaque and 2 cm up, and the camera's depth range is
  15–95 m instead of 0.1–140 m.
- `tools/zone_check.mjs <url> <outDir>`: Rita works the pipe machine, is promoted and led to a post; checks the
  ring shows at the post, fades, never follows her, and the zone stays put.

- **Buildings fade**: `fadeGroup()` hides a roof and the camera-side wall while the owner is inside or behind it.
- **Navigation is generated**: `buildNav()` takes the spots people use, the doorways and a point off every corner of
  every collision box; `siteBounds()` is the one place the walkable area is defined.
- **Power runs overhead**: generator -> switchboard on its own stand -> timber poles -> the junction-box pole at the
  crate pad, the barn's door lamps, the dock floodlight and the office.
- **Ground detail**: grass creeping along the fences, worn paths between the buildings, oil and puddles, each kind
  merged into one mesh (`groundDetail()`).
- **Camera**: `VIEW_W 11 / VIEW_H 13`, so a phone shows a slice of the site rather than one room.
- **HUD**: a management bar along the bottom (Orders, Workers, Machines, Issues, Production, Storage, Finance, Town)
  opens the office at that page from anywhere, with badges; chips for the day clock (a working day is 8 minutes),
  crew and open issues; an objectives panel ticks off the charter with the hint underneath (tap to fold).

## Progression (game/progression.js)

Everything that grows with the company level is data in one file, covering all 16 levels of the strategy
doc: the level ladder (titles, new system, product, money goal), hiring caps per role and level, how far
workers can train (level 1: 5, each level +2), the training curve, every upgrade and piece of equipment as
a row with `tiers` (how many steps open at which level) and a price curve past the hand-set first steps,
order size and price scaling, and facility needs (one toilet stall per four people). The game reads only
this table, so a new level or upgrade is a new row. The office's Charter tab shows "The road ahead": every
level and what it opens, generated from the same rows. `eslint.config.mjs` (run by the packager) catches
names used but never defined, the bug class that froze build 0.9.
